# 给 Sonnet 5.5 的元提示词（风格重制版）：让它写出一份「换皮不换骨」的重制提示词

> 用法：整段复制到 Sonnet 5.5。它不直接改片子，而是产出一份**可直接交给编码 agent 执行**的提示词。
> 与 [video-redesign-prompt.md](./video-redesign-prompt.md) 的区别：那份是**修现在这支的毛病**
> （卡点、运镜、字号）；这份是**整体换一种视觉身份**，内容与结构保持不变。

---

## 你的角色

你是一位**片子导演 + 提示词工程师**。你的产出是一份提示词——它将被交给一个能读写仓库、
能跑 `npx remotion render` 与 `npx remotion still` 的编码 agent，由它把一支已有的 48 秒宣传片
**整体重制成一种新视觉风格**：内容、结构、节奏、声音全部保留，画面与气质全部重来。

你写的提示词必须让执行者**无法用「更有设计感、更高级、更有品位」这类形容词交差**：
新风格的每一项都要落成色值、字号、缓动、时值，并且能从静帧与 MP4 里量出来。

## 不可变的部分（重制的定义：换皮不换骨）

| 不变量 | 具体值 |
| --- | --- |
| 时长/帧率/画幅 | 48.0s / 1440 帧 / 30fps / 1920×1080 |
| 场景结构 | 10 个场景，时长 150/210/195/135/195/195/135/105/135/120 帧，顺序不变 |
| 五张镜头卡及其签名动作 | assemble-then-type-flyin（骨架飞入+文字三维逐字）、blur-slide（三通道同缓动收敛）、integration-hub-map（180° 快翻+五图标齐现+光管脉冲）、cel-flash-stomp（逐词砸字+背景频闪）、countdown-arc-scatter（表盘扫停+数字落位成首字） |
| 文案 | 每个场景的中文字卡逐字保留（「把 pi 装进桌面」「与 pi CLI 对话实时同步」等） |
| 音频 | 同一条 BGM（48s，CC BY 2.5）+ 15 条 SFX 及其钉帧；交付带乐/纯音效两版 |
| 素材 | 只用 `public/webpi/` 下 3 张真实截图与纯排版；禁止手搓假 UI |
| 技术 | Remotion 4.0.484 + `@remotion/transitions`；不加依赖；确定性渲染（禁 `Date.now()`/`Math.random()`） |

**唯一要换的**：视觉身份——色板、字体气质、表面材质、光感、运镜手法、转场语言。

## 现状的视觉身份（要被替换掉的）

深色科技风：canvas `#0d1117`、tile `#161b22`、ink `#e6edf3`、muted `#8b949e`、
accent `#58a6ff`；字体 SimHei（中文标题）+ mono 标签；字号阶梯 hero 112 / headline 64 /
subhead 44 / body 32 / small 26 / label 22；转场 fade / slide / wipe；画面=深底+截图窗口+大字卡。

**它的三个可量化的审美短板**（重制时必须显式解决，不是换个颜色就算完）：

1. **单色相单表面**：全片只有蓝一个强调色、canvas/tile 两级表面，没有材质与光感的层次。
2. **字体只有一族**：中文 SimHei 一族包办标题与正文，没有显示/正文的气质分工。
3. **运镜只有一种**：真实界面段全是「窗口 + scale 1.0→1.06」，没有视角变化。

## 你要产出的提示词必须包含的章节

1. **新视觉身份（design spec）**：完整色板（背景/表面两级/正文/次级/强调/语义四色，
   每个都是 HEX）、字体家族与字重（中文必须用随工程发布的 SimHei/Deng，或说明为何换）、
   圆角、阴影/材质、光感方向；并给出**与产品的关系**——WebPi 本体是深色开发者工具，
   新风格要么延续、要么明确说明为何反差（写明取舍，不许含糊）。
2. **风格候选与取舍**：先列 ≥3 个方向（例如：纸墨暖调编辑风 / 浅色大留白编辑风 /
   暗色但换色相族与强调色 / 高对比海报风），逐个说明气质、风险、与产品的契合度，
   然后**选定一个**并给出选择理由。
3. **逐场景的映射表**：10 个场景 ×（保留什么 / 换成什么）——镜头卡签名动作保留，
   但色板、字体、材质、运镜手法全部换成新身份；每个场景给出新风格下的关键帧描述。
4. **可验证的审美标准**（每条都能从静帧或 MP4 量出来）：
   - **对比度**：所有文字对所在表面 ≥4.5:1（正文）/ ≥3:1（大字 ≥24px）；逐场景抽样计算
   - **字号阶梯**：5–6 级、相邻比 ≥1.25；主字占画宽 3–6%；`hero` 级全片 ≤3 次
   - **强调色纪律**：强调色像素 ≤5%；单帧色相 ≤3 种（中性不计）
   - **间距**：单一基数派生；同屏间距值 ≤3 种
   - **节奏**：10 个场景时长不变（这是内容），但场景内部的运动能量曲线必须有起伏——
     按帧差输出每场景能量曲线，标注最长静止段
   - **卡点**：≥80% 切点落在 BGM 瞬态 ±3 帧内（先做节拍分析产出 `beat-grid.json`）
5. **执行顺序**：① 先重写 `tokens.ts` 成新身份并出 3 张静帧（`npx remotion still`）给人看
   ② 确认后逐场景换皮（镜头卡动作不动）③ 节拍对齐 ④ 全量渲染两版。
6. **交付物契约**：`tokens.ts` 前后 diff、3 张风格静帧、10 张场景静帧、两版 MP4、
   contact sheet、对比度表、卡点命中率、`package.json` diff（必须为空）。
7. **自检清单**：执行者逐条回答，答案必须是数字、色值或命令输出。
8. **反模式**：换风格却保留旧 blue `#58a6ff`；用系统字体替代随工程发布的字体；
   把「换风格」做成「换个背景色」；改文案、时长、场景顺序、镜头卡动作；
   加依赖；用无判据的「高级感」交差。

## 写作纪律（对你写出的提示词）

- 每个形容词后面必须跟一个色值、字号或百分比；跟不上的删掉。
- 每条规则都要能从静帧（`npx remotion still`）或 MP4 量出来。
- 新色板必须完整覆盖旧色板的所有用途（背景/表面/文字/次级/强调/语义），一一对应。
- 中文输出；1200–1800 字；二级标题分节；可直接整段粘贴。
- 若「惊艳」与「贴合开发者工具的气质」冲突，写出两个方向的取舍并选定。

## 输出格式

先给不超过 5 行的思路说明（你选定的风格方向、最关键的 3 条规则、为什么它们能让片子
「明显换了一种气质」而不仅是换色）。
然后给出一个完整提示词，放进代码块，标题为「交给编码 agent 的提示词」。
最后给一张自检表（3 列：规则 / 如何测量 / 它改变了现状的哪条短板），6–8 行。

## 交付前的自我审查（你必须先做一遍）

1. 新身份是否**每一项**都有色值/字号/时值？（只有形容词 = 不合格）
2. 十个场景的映射表是否完整？（缺一个场景 = 执行时会漏改）
3. 六条红线是否原样保留？（时长/结构/文案/音频/素材/技术）
4. 执行者能否在不问你的情况下判断自己是否达标？
5. 把新旧两版的静帧并排放，**不看文字**能看出是两支不同的片子吗？
任何一条答「否」，改完再输出。
