# 给 Sonnet 5.5 的元提示词（视频版）：让它写出一份「能把宣传片做得更好看」的提示词

> 用法：整段复制到 Sonnet 5.5。它不直接改片子，而是产出一份**可直接交给编码 agent 执行**的提示词。
> 下面的事实全部取自 `C:\Users\citie\webpi-shotcraft` 的实测，不要替换成别的项目。
>
> ⚠️ 与「应用界面版」的区别：目标不是 Next.js 界面，而是**成片**（Remotion 工程 → MP4）。
> 判据必须是「能从 MP4 里量出来」的东西（亮度、墨迹占比、帧差、切点 vs 音频瞬态、音量），
> 而不是 CSS 变量与 DOM。

---

## 你的角色

你是一位**片子导演 + 提示词工程师**。你的产出不是代码，不是分镜，而是一份提示词——
它将被交给一个能读写仓库、能跑 `npx remotion render` 的编码 agent，由它来重制这支宣传片。

你写的提示词必须让执行者**无法用「更高级、更电影感、更抓人」这类形容词蒙混过关**：
每一条要求都要落成可命令、可测量、可复算的判据。

## 项目事实（硬约束，不得编造）

**成片**：WebPi Desktop 的宣传片。48.0 秒 / 1920×1080 / 30fps / 1440 帧，无旁白（中文大字卡驱动），
10 个场景用 `TransitionSeries` 串场，交付两版（带 BGM / 纯音效，同一个 `bgm` 开关）。

**技术栈（必须保持，不许加依赖）**

- Remotion **4.0.484** + `@remotion/transitions` **4.0.484** + React 19 + TypeScript
- 工程：`src/webpi/`（`Main.tsx` 时间线、`shots/*.tsx` 场景、`tokens.ts` 设计令牌）
- 设计令牌：`T`（canvas `#0d1117`、tile `#161b22`、ink `#e6edf3`、muted `#8b949e`、accent `#58a6ff`）、
  `F`（SimHei / Deng / mono，字体随工程发布在 `public/fonts/`）、
  `TYPE`（hero 112 / headline 64 / subhead 44 / body 32 / small 26 / label 22）、
  `SPACE`（edge 128 / block 36 / tight 16）
- 素材：`public/webpi/` 下 3 张**真实界面截图**（home / sessions / settings）；`public/audio/` 有
  11 个 SFX 与 1 条 48s BGM（CC BY 2.5，需署名）
- 五张镜头卡（签名动作不许降档）：`assemble-then-type-flyin`（骨架飞入 + 文字三维逐字落位）、
  `blur-slide`（y/blur/opacity 三通道同缓动）、`integration-hub-map`（180° 快翻 + 五图标齐现 +
  光管脉冲）、`cel-flash-stomp`（逐词砸字 + 背景层频闪）、`countdown-arc-scatter`（表盘扫停 +
  数字落位成标题首字符）

**实测到的现状问题（这是立论基础，必须在提示词里被引用、被解决）**

1. **切点与音乐毫无关系**：代码里 `beat|onset|bpm` 出现 **0 次**，10 个切点全是 150/210/195/135/
   195/195/135/105/135/120 这样的整数帧；BGM 是从原曲第 22 秒整截的，没按瞬态裁剪。
   观众感觉"节奏平"的原因就在这里——不是运镜不够花，是**声音和画面各走各的**。
2. **界面段没有运镜**：3 张真实截图，只做了「窗口 + 缓慢 scale 到 1.06」；video-shotcraft 模板自带的
   2.5D 页面相机（PageCam + `layout.json` 元素坐标）完全没用。这是"看起来像 PPT 换页"的主因。
3. **字号阶梯只用了 13 次**：全片 6 个字号级别共出现 13 次（label×5、hero×2、headline×2、
   subhead×2、body×1、small×1），多数场景只有 1–2 级——层级是平铺的。
4. **同一张截图复用**：`webpi-home.png` 出现在 2 个场景里（品牌段与桌面段），第二次出现没有任何
   视角或裁切差异。
5. **转场是机械选择**：fade / slide / wipe 各按位置分配，没有一处是"因为内容关系"才选的。

**不可破坏（执行者红线）**

- 时长 48.0s ±0.5s、1920×1080、30fps；无旁白
- 两版交付（带 BGM / 纯音效），`bgm` 布尔 prop 必须保留
- 五张镜头卡的签名动作不许降档；`tokens.ts` 的 `TYPE`/`SPACE`/`T`/`F` 只能扩展不能改值
- 不加任何依赖；`package.json` 的 diff 必须为空
- 只用 `public/` 里的真实素材与纯排版，**禁止手搓假 UI**

## 你要产出的提示词必须包含的章节

1. **角色与边界**：只改 `src/webpi/` 的视觉与节奏，不动 `tokens.ts` 的既有值、不动镜头卡签名动作。
2. **现状诊断**：把上面 1–5 条带数字引用。
3. **审美标准（每条可从 MP4 量出来）**——至少覆盖：
   - **卡点**：先把 BGM 做节拍分析（BPM + 相位 + kick/snare/hihat 三分类），产出 `beat-grid.json`；
     要求 ≥80% 的切点落在瞬态 ±3 帧内；≥6s 的长场景内部至少 1 个重音落在拍上
   - **运动能量（防前端倒出后冻结）**：按 0.5s 窗口算帧差均值；场景前 80% 内不得出现连续
     >1.5s 的低能量段；全片至少 2 个刻意静止段（≥1s），且静止前必须有运动铺垫
   - **层级**：每场景 ≥2 个字号级、全片 ≥4 级；主字占画宽 3–6%；`hero` 级全片 ≤3 次；
     字卡 ≤2 行、单行 ≤12 个汉字
   - **构图**：每场景 5–12 个元素；主元素占画面 ≥25%；除刻意黑场外不得出现空屏
   - **色彩**：强调色像素 ≤5%；单帧内色相 ≤3 种（中性不计）；至少 3 个深度层
   - **音频**：交付两版；无 >0.6s 的静音段（刻意停顿 ≤1 处）；mean −28…−18dB、max ≤ −1dB
   - **运镜**：3 个界面段各自必须有真实位移（推近/横移/2.5D 视差之一），位移幅度可量
     （起止帧的裁切窗口变化 ≥8%）
4. **执行顺序**：① 音频分析出 `beat-grid.json` 并对齐现有切点（只报偏离，不改画面）
   ② 重排时间线到拍上 ③ 界面段换 2.5D 运镜 ④ 铺开其余场景 ⑤ 全量测量。每阶段结束停下等人确认。
5. **交付物契约**：改哪些文件、每阶段要交什么证据（`beat-grid.json`、切点命中率、能量曲线、
   静帧测量表、两版 MP4、contact sheet、`package.json` diff）。
6. **自检清单**：执行者改完逐条回答，答案必须是数字或命令输出。
7. **反模式**：无判据的「电影感」；把运镜当成加特写；为卡点而卡点导致语义断裂（切点必须同时
   是语义句号）；改镜头卡签名动作；加依赖；把"更快"当"更好"。

## 写作纪律（对你写出的提示词）

- 每个形容词后面必须跟一个数或一条命令；跟不上的删掉。
- 每条规则都要能从 MP4 或工程文件量出来；写不出测量方式的不要写。
- 只能引用项目已有的色值与字号；新增只能扩展 `tokens.ts` 并说明理由。
- 中文输出；1200–1800 字；二级标题分节；可直接整段粘贴。
- 若"审美"与"可验证"冲突，选可验证并写明取舍。

## 输出格式

先给不超过 5 行的思路说明（你认为最关键的 3 条规则、为什么它们能解决上面 1–5 条问题）。
然后给出一个完整提示词，放进代码块，标题为「交给编码 agent 的提示词」。
最后给一张自检表（3 列：规则 / 如何测量 / 命中哪条现状问题），6–8 行。

## 交付前的自我审查（你必须先做一遍）

1. 每条规则是否都有数字或命令？
2. 是否可能被「更有电影感」这类套话钻空子？
3. 是否明确：六条红线（时长/双版本/镜头卡签名/tokens 不改/无新依赖/只用真实素材）？

任何一条答「否」，改完再输出。
