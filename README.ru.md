# WebPi Desktop

[English](./README.md) | [中文文档](./README.zh-CN.md) | [日本語](./README.ja.md)

**WebPi Desktop — настольный клиент для [pi coding agent](https://github.com/earendil-works/pi), построенный на WebPi.** Это обычное окно с иконкой в трее: запуск приложения запускает сервер, выход останавливает его, а **Node.js устанавливать не нужно**. Он читает те же файлы конфигурации, учётных данных и сессий, что и pi: разговор, начатый в терминале, открывается в приложении — и наоборот.

![Начальный экран WebPi Desktop: список сессий, панель Get Started и пункты «Модели», «Навыки», «Настройки»](./docs/screenshot.png)

В репозитории **две вещи**, и они используют одни данные pi (сессии и учётные данные лежат в `~/.pi/agent`):

| | Что это | Как запустить |
| --- | --- | --- |
| **WebPi Desktop** | Настольный клиент — своё окно и значок в трее, сервер запускается и останавливается вместе с приложением | Установщик или портативная сборка со [страницы релизов](https://github.com/citie114514/pi-web/releases/latest), либо `npm run desktop` |
| **WebPi** | Браузерный интерфейс, на котором он построен: сессии, чат, модели, файлы, терминал | Глобальная команда `webpi` или `/webpi` внутри pi |

## Чем это не является

На GitHub много фронтендов для pi, и имена пересекаются, поэтому границы стоит обозначить сразу:

- **Это не мост к терминалу.** WebPi — настоящий веб-интерфейс (Next.js), который читает и пишет файлы сессий pi и RPC, а не TUI, перенесённый в браузер через xterm.js.
- **Это не отдельный agent runtime.** Управление сессиями, настройка моделей и входа, выполнение агента — всё идёт через вышестоящий `pi`. Это оболочка вокруг него.
- **В основе — `agegr/pi-web`**, откуда взялся веб-интерфейс. WebPi Desktop добавляет настольную оболочку, упаковку и запуск, удобный для Windows.

WebPi — сборка на основе [pi-web](https://github.com/agegr/pi-web). Само приложение — работа вышестоящего проекта; этот репозиторий добавляет команду `webpi`, настольный клиент WebPi Desktop, пакет для Pi, запуск, удобный для Windows, и имя WebPi. Что именно отличается — в [docs/webpi.md](./docs/webpi.md), настольная сборка — в [docs/webpi-desktop.md](./docs/webpi-desktop.md), порядок слияния с вышестоящим репозиторием — в [docs/upstream-sync.md](./docs/upstream-sync.md), а исходная точка форка — в [docs/upstream-inventory.md](./docs/upstream-inventory.md).

## Возможности

- **Рабочая область сессий**: просмотр, продолжение, переименование, экспорт и удаление диалогов с группировкой по проектам, а также состояние выполнения, расход контекста, стоимость и сведения о сжатии.
- **Два способа ветвления**: **New session** создаёт отдельный файл сессии от более раннего сообщения, **Edit from here** создаёт ветку внутри текущей сессии.
- **Работа с файлами проекта**: просмотр и загрузка файлов, сравнение изменений Git, предпросмотр исходников, Markdown, изображений, аудио, PDF и DOCX с автоматическим обновлением.
- **Git worktree**: переключение рабочих копий из боковой панели; сессии одного репозитория остаются вместе.
- **Настройка в браузере**: вход в провайдеры и ключи API, модели, тесты моделей, пакеты плагинов и навыки — не выходя из браузера.
- **Интерфейс на английском, упрощённом и традиционном китайском**: язык определяется браузером, переключатель — в верхней панели.

## Быстрый старт

### Настольное приложение

Загрузите сборку для своей платформы со [страницы релизов](https://github.com/citie114514/pi-web/releases/latest) и запустите её. Запуск приложения запускает сервер WebPi, выход из приложения останавливает этот сервер. Больше ничего устанавливать не нужно.

| Платформа | Установщик | Портативная версия |
| --- | --- | --- |
| Windows x64 | `WebPi-Desktop-Setup-<version>-x64.exe` (для текущего пользователя, без прав администратора) | `WebPi-Desktop-Portable-<version>-x64.exe`, `WebPi-Desktop-<version>-win-x64-portable.zip` |
| Linux x64 | `WebPi-Desktop-<version>-linux-x86_64.AppImage`, `WebPi-Desktop-<version>-linux-amd64.deb` | `WebPi-Desktop-<version>-linux-x64-portable.zip` |
| Linux arm64 | `WebPi-Desktop-<version>-linux-arm64.AppImage`, `WebPi-Desktop-<version>-linux-arm64.deb` | `WebPi-Desktop-<version>-linux-arm64-portable.zip` |
| macOS x64 / arm64 | `WebPi-Desktop-Setup-<version>-<arch>.dmg` | `WebPi-Desktop-<version>-mac-<arch>-portable.zip` |

О том, как приложение управляет сервером, о портативном режиме и предупреждениях подписи читайте в разделе [Настольное приложение](#настольное-приложение).

### Команда `webpi`

Требуется Node.js 22.19.0 или новее. Проверьте версию командой `node --version`, затем установите этот репозиторий как глобальную команду:

```bash
git clone https://github.com/citie114514/pi-web
cd pi-web
npm install
npm run build
npm install -g .
webpi
```

Когда сервер готов, `webpi` открывает браузер. Если этого не произошло, откройте напечатанный адрес — по умолчанию [http://127.0.0.1:30141](http://127.0.0.1:30141). WebPi по умолчанию слушает только `127.0.0.1`. Удалить команду можно так: `npm uninstall -g webpi`.

### Как пакет Pi

Установите этот каталог как пакет Pi, чтобы запускать сервер прямо из pi:

```bash
pi install /path/to/pi-web
```

Затем выполните `/webpi` в TUI pi, чтобы запустить сервер и получить адрес. `/webpi --port 8080` передаёт параметры тому же лаунчеру. Сервер, запущенный так, останавливается вместе с этой сессией pi; если он должен пережить выход из TUI, запускайте его из оболочки или настольного приложения.

### Настройка модели

Если провайдер моделей ещё не настроен, откройте панель **Models** и войдите или добавьте ключ API. Панель использует хранилище моделей, настроек и учётных данных самого pi, поэтому изменение видно в обоих интерфейсах. Команда `/login` в CLI pi записывает те же учётные данные.

Пакет вышестоящего проекта по-прежнему доступен как `npx @agegr/pi-web@latest`, если он нужен без этого слоя упаковки.

## Настольное приложение

Настольная сборка — то же приложение в отдельном окне, со значком в трее и полноценным жизненным циклом:

- **Запуск приложения запускает службу, выход останавливает её.** Сервер, запущенный не этим приложением, не останавливается: если порт уже занят другим экземпляром WebPi, приложение поднимает свой на свободном порту, поэтому выход всегда безопасен.
- **При закрытии окна приложение спрашивает, что делать** — свернуть в трей или закрыть всё — и может запомнить выбор. Изменить его можно в меню трея.
- **Ссылки открываются в системном браузере**: URL из ответа модели уходит в браузер по умолчанию, а не во встроенное окно (в систему передаются только http, https и mailto).
- **Меню трея** также показывает и скрывает окно, перезапускает службу и завершает работу. Если служба неожиданно завершилась, диалог предложит перезапустить её или выйти.
- **Портативный режим**: портативные архивы хранят настройки внутри распакованного каталога, поэтому каталог целиком можно перенести на флешку. Данные самого pi остаются в `~/.pi/agent`.

Сборки не подписаны, поэтому Windows SmartScreen и macOS Gatekeeper предупреждают при первом запуске; в [docs/webpi-desktop.md](./docs/webpi-desktop.md) описаны предупреждения, портативный режим, подпись кода и процесс выпуска в CI.

Собрать из исходников:

```bash
npm run desktop          # запуск из исходников
npm run desktop:dist     # установщик и портативная сборка для текущей платформы
```

Артефакты попадают в `release/`. `.github/workflows/desktop-release.yml` собирает все платформы, запускает каждый артефакт для проверки и публикует релиз.

## Настройка

Для порта и имени хоста параметры командной строки имеют приоритет над соответствующими переменными окружения. `--no-open` или `PI_WEB_NO_OPEN=1` отключают автоматическое открытие браузера. `webpi --help` (или `-h`) печатает параметры запуска и завершается с кодом 0, не запуская сервер; неизвестные параметры приводят к ошибке.

Переменные окружения сохраняют имена `PI_WEB_*` из вышестоящего проекта, поэтому существующие инструкции и обёртки продолжают работать.

| Параметр или переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `--help`, `-h` | Показать параметры запуска и выйти | — |
| `--port <порт>`, `-p <порт>`, `PORT` | Порт сервера | `30141` |
| `--hostname <хост>`, `-H <хост>`, `PI_WEB_HOSTNAME` | Имя хоста для привязки | `127.0.0.1` |
| `--no-open`, `PI_WEB_NO_OPEN=1` | Не открывать браузер автоматически | Браузер открывается |
| `PI_WEB_SKIP_VERSION_CHECK=1` | Отключить проверку обновлений WebPi | Не задано |
| `PI_WEB_ALLOWED_HOSTS` | Дополнительные точные имена прокси или хостов, через запятую | Не задано |
| `PI_WEB_PASSWORD` | Включить вход по паролю в браузере; клиенты API могут использовать Basic Auth с именем `pi` | Аутентификация отключена |
| `PI_WEB_IDLE_TIMEOUT_MS` | Тайм-аут простоя сессии в миллисекундах, до `2147483647`; `0` отключает остановку по простою; некорректные значения заменяются значением по умолчанию | `600000` (10 минут) |

Например:

```bash
webpi --help
webpi -p 8080 -H 0.0.0.0 --no-open
```

### Поведение при запуске

- Если на запрошенном порту уже работает WebPi, он используется повторно: `webpi` печатает его адрес и завершается, вместо того чтобы поднять второй сервер над теми же файлами сессий.
- Порт, занятый другой программой, пропускается; лаунчер проверяет до десяти последовательных портов и печатает использованный. Зарезервированные порты, которые отклоняет сам Next.js, также пропускаются.
- `--port 0` означает, что свободный порт выберет операционная система.
- Автономная команда `webpi` работает до остановки по `Ctrl+C`.

### Удалённый доступ

Привязка к адресу, отличному от loopback, открывает агента, способного выполнять высокопривилегированные действия. Даже в доверенной локальной сети задайте длинный случайный пароль:

```bash
PI_WEB_PASSWORD='длинный-случайный-пароль' webpi --hostname 0.0.0.0
```

Пароль не шифрует соединение. Не публикуйте WebPi в интернете по обычному HTTP; используйте HTTPS через доверенный обратный прокси или VPN. Если обратный прокси передаёт внешнее имя хоста, добавьте это точное имя в `PI_WEB_ALLOWED_HOSTS`. Этот список не меняет адрес, к которому привязывается WebPi.

### HTTP-прокси

Серверные запросы к моделям и API учитывают стандартные переменные `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY`.

macOS или Linux:

```bash
HTTP_PROXY=http://127.0.0.1:7890 \
HTTPS_PROXY=http://127.0.0.1:7890 \
NO_PROXY=localhost,127.0.0.1 \
webpi
```

Windows PowerShell:

```powershell
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
$env:NO_PROXY = "localhost,127.0.0.1"
webpi
```

## Примечания

- **Данные агента**: по умолчанию WebPi читает данные pi из `~/.pi/agent`, включая файлы сессий в `sessions/<закодированный-cwd>/<метка-времени>_<uuid>.jsonl`. Переменная `PI_CODING_AGENT_DIR` позволяет указать другой каталог агента pi.
- **Доступ к файловой системе**: WebPi должен читать каталог данных агента и рабочие каталоги, записанные в сессиях. Чтобы использовать существующие сессии, запускайте его в том же файловом окружении, что и pi.
- **Общая конфигурация**: панель моделей использует хранилище моделей, настроек и учётных данных pi, поэтому изменения видны в обоих интерфейсах.
- **Границы доступа к файлам**: файловый браузер ограничен рабочими каталогами, выбранными в WebPi, и известными ему корнями проектов и сессий; это не универсальный файловый менеджер.
- **Git worktree**: видимость переключателя, создание и удаление worktree описаны в [Worktrees in WebPi](./docs/worktrees.md).
- **Разработка на основе WebPi**: обёртки могут подключаться к контекстному меню строки сессии и регистрировать удержание сессии расширения — см. [Интеграция для потребителей](./docs/downstream-integration.md).

## Разработка

```bash
npm install
npm run dev
```

Сервер разработки работает на [http://127.0.0.1:30141](http://127.0.0.1:30141). Основные проверки:

```bash
npm test
node_modules/.bin/tsc --noEmit
npm run lint
```

Не запускайте `next build` или `npm run build` во время обычной разработки: они пишут в `.next/` и могут мешать серверу разработки. Сборка предназначена для выпуска.

Документы для контрибьюторов: [Слияние с вышестоящим репозиторием](./docs/upstream-sync.md) (форк отслеживает upstream еженедельно), [Интернационализация](./docs/i18n.md), [Процесс выпуска](./docs/release.md).
